# Compact Script and explicit scalar adapters

Use `script version 2 compact` as the first line to opt into compact generated ABAP and a bounded 120,000-character source budget. Ordinary v1, v2 and ABAP cells retain the 60,000-character guard. This is a Notebook guard, not a fixed DDIC source-field limit: ZBN_SRC-SOURCE is STRG. SAP native compilation and existing execution budgets still apply. Saved ordinary v1/v2 envelopes retain their original generated bytes and remain reopenable.

Compact mode uses small inline ABAP macros for field binding and native declarations. It reuses declarations, never stale row addresses. Every field use still unassigns, reassigns against the current native row and checks success. Dynamic lookup key names are immutable constants declared before conditional code, so a skipped branch cannot leave a later query key empty. Numeric assignments, search/sort/duplicate precedence, schema checks and source-line mapping are retained.

## Explicit defaults

```text
script version 2 compact
dataset working = "read_stage" named "WORKING"
defaults working with ACCOUNT "ACCOUNT_NA", GEO_DRIVERS "GDRVS_NA", TIME "TIME_NA"
publish working as "NORMALIZED"
```

Each default is supplied by the author; the helper contains no model-specific constants. Only native `IS INITIAL` fields are replaced, including blank character fields or numeric zero if explicitly named. Noninitial fields are preserved. Schema names, duplicate defaults and native conversion are validated before row mutation, even for empty tables. Values use the target native field type and its assignment conversion/rounding. Defaulting is not aggregation, member authorization or final writeback validation; those retain their own existing boundaries.

## Scalar lists and native text conversion

```text
let ids = split(input("MEMBER_IDS"), ",")
let flags = split(input("FLAGS"), ",")
let position = integer(0)
for id in ids
  position = position + 1
  let flag = trim(at(flags, position))
  if not initial(flag)
    if signed(flag) != 0
      message trim(id)
    end
  end
end
let compactText = no_gaps(" A B C ")
let memberId = concat("VISIBLE_PREFIX_", numeric_text(signed("1.5"), 3))
```

- `split(text, separator)` uses native ABAP SPLIT INTO TABLE, retaining its order, empty-position and trailing-separator semantics. It performs no sorting, deduplication, trimming or filtering. Empty separator fails.
- `trim(text)` removes leading/trailing SAP spaces and preserves interior spaces. `no_gaps(text)` uses actual `CONDENSE ... NO-GAPS`.
- `at(ids, position)` is one-based and returns an empty string for an absent/nonpositive position. Callers explicitly decide what absence means.
- `numeric_text(value, width)` converts the original numeric operand directly to native ABAP N(width), then returns all digits as text. Width is 1-255; no intermediate integer, float or decimal cast is introduced. Overflow/rounding/negative handling follows SAP's native conversion. Prefixes and member lookup stay visible in the authored Script.

The positional filtering example is generic, not the DEMREVID003 business rule. Where the original first condenses, sorts and deduplicates separate ID/flag range tables before pairing, the port must reproduce that sequence explicitly with typed working tables. Changing that sequence to raw input-position pairing changes calculation behavior.

Native verification tool: `tools/check-script-compact.cjs`, evidence `docs/evidence/native-script-compact.json`. It checks complete table operations in compact mode, defaults, scalar lists, native NUM03 boundary equivalence, a generated cell exceeding 60,000 characters through save/compile/run/reopen, and deliberate invalid-input failures. Source-size audit `tools/measure-script-compact.cjs <directory>` is read-only and does not rewrite calculation files.
